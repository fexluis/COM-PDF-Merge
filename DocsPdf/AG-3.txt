### 1.2 Requisitos **reales** de CRDT (leídos en `Core\Sync\SyncInitializer.cs`)
| Regla | Evidencia en código |
|---|---|
| **PK única de una sola columna** | `GetPrimaryKeyColumn(...)` → devuelve **un** `string`; `if (string.IsNullOrEmpty(pkColumn))` aborta |
| **PK `INTEGER/TEXT PRIMARY KEY NOT NULL` sin `AUTOINCREMENT`** | `ReplacePrimaryKeyWithNotNull` (L674–693) reemplaza `... PRIMARY KEY AUTOINCREMENT` por `... PRIMARY KEY NOT NULL`; `EnsurePrimaryKeyNotNull` (L438–466) verifica `notnullValue == 1` |
| **Sin `FOREIGN KEY`** | `hasFks` → `RemoveForeignKeyConstraints` (L746) |
| **Sin `NOT NULL` en columnas no-PK sin `DEFAULT`** | `CheckNotNullWithoutDefault` (L767–780): `name != pkColumn && notnull == 1 && string.IsNullOrEmpty(dflt_value)` → si existe, **reconstruye la tabla** |
| **UNIQUE**: sólo se elimina automáticamente en `config`, `usuarios`, `salvedades_conflictos`, `BaseGastosTerrestre` | L457 `needsUniqueRemoval` |
| **Se recrea la tabla si algo no cumple** (con DROP de vistas dependientes) | L469–508 |
| **Filtro obligatorio por `subunidad`** | `CrdtTables[]` L21–28 + convención `WHERE (subunidad = @S OR subunidad = '' OR subunidad IS NULL)` |

## 2. Respuesta directa: ¿cómo usar la información de `idvinculacion`?

**Concepto:** una vinculación histórica **demuestra** que un Tercero `P` fue habilitado/dictó la Asignatura `C` del Programa `Pr` en el Semestre `S`. Por tanto `idvinculacion` es la **evidencia** del par `(P, C)` dentro de `(Pr, S)`.

```
FormVerVinculaciones · Vista "Por Semestre"
   Nodo: PROGRAMA ▸ SEMESTRE ▸ (Sede/Periodo) ▸ SesionListItem
                                                    │  IdVinculacion, IdTercero, IdPrograma*, Semestre, IdSede, IdPeriodo
                                                    ▼
                    Derivación (consulta a `vinculaciones` base)
                                                    ▼
              terceros_asignaturas (P × Programa × Asignatura × Semestre)
                                                    ▼
                      AgAsignadorTercero  →  mejor cruce S+C+P  →  menos vacantes
```
`*` `IdPrograma` está en `SesionListItem` (viene de `vw_SesionesDetalle`); `IdAsignatura` no, por lo que la derivación baja a la tabla base `vinculaciones`.

**Consulta de derivación (idempotente, recalculando el peso):**
```sql
-- Backfill / re-sincronización del pool a partir del histórico de vinculaciones
SELECT  v.idtercero    AS IdTercero,
        v.idprograma   AS IdPrograma,
        v.idasignatura AS IdAsignatura,
        v.semestre     AS Semestre,
        COUNT(DISTINCT v.id) AS VecesAsignada,
        MAX(COALESCE(NULLIF(v.fecha_fin,''), NULLIF(v.fecha_inicio,''))) AS FechaUltimaAsignacion
FROM vinculaciones v
WHERE v.idtercero    IS NOT NULL AND v.idtercero    > 0
  AND v.idasignatura IS NOT NULL AND v.idasignatura > 0
  AND v.idprograma   IS NOT NULL AND v.idprograma   > 0
  AND (@IdSede    IS NULL OR v.idsede    = @IdSede)
  AND (@IdPrograma IS NULL OR v.idprograma = @IdPrograma)
  AND (@Semestre  IS NULL OR v.semestre  = @Semestre)
  AND (@IdPeriodo IS NULL OR v.idperiodo = @IdPeriodo)
GROUP BY v.idtercero, v.idprograma, v.idasignatura, v.semestre;
```

## 3. Cuatro mecanismos de población del pool

### 3.1 M1 — **Derivación histórica (backfill)** · `TerceroAsignaturaSyncService.DerivarDesdeVinculaciones(filtro)`
- Idempotente: **recalcula** `veces_asignada` (no incrementa) → se puede re-ejecutar sin inflar.
- `origen = 'HISTORICO'`, `activo = 1` (configurable: sólo `>= N` vinculaciones).
- Disparadores:
  - **Migración V49**: backfill inicial de todo el histórico (`subunidad = ''` o la activa).
  - **Botón "Sincronizar pool"** en `FormTerceros` (por tercero / global).
  - **Menú contextual en `FormVerVinculaciones`** (por nodo: asignatura, semestre o programa).

### 3.2 M2 — **Captura incremental automática (hooks)**
| Hook | Punto exacto | Datos que guarda |
|---|---|---|
| **H1** | `FormSesionesAcademicas.GuardarAsync` → dentro de la **misma transacción** (tras `InsertVinculacion`/`UpdateVinculacion` + `InsertSesiones`) | `idTercero, idPrograma, idAsignatura, semestre, activo=1, veces_asignada++` |
| **H2** | `AgPromotorVinculaciones` → tras el `Commit` de la promoción | idem con `origen='AG_APROBADO'` |
| **H3** | `FormSesionesAcademicas.btnEliminar_Click` | **no** deshabilita; sólo deja de incrementar (el pool es histórico acumulativo) |

### 3.3 M3 — **Captura manual** (UI `FormTerceros`, §6)

### 3.4 M4 — **Aprendizaje del AG**
- Al aprobar/promover, las vinculaciones aprobadas alimentan el pool (`origen='AG_APROBADO'`), por lo que **cada ciclo del AG mejora** las asignaciones siguientes.
- `veces_asignada` + `prioridad` alimentan **F4** (afinidad docente↔asignatura) del fitness.

### 3.5 Contrato de escritura (upsert determinista, conforme a CRDT)
```csharp
// Pseudocontrato del repositorio (dentro de la transacción del llamador)
public Result Upsert(TerceroAsignatura fila)
{
    // 1) PK determinista: evita duplicados al converger réplicas CRDT
    fila.Id = TerceroAsignaturaKey.Calcular(fila.IdTercero, fila.IdPrograma, fila.IdAsignatura, fila.Semestre);
    // 2) Si el PK existe y la clave coincide -> UPDATE (activo, prioridad, veces++, fecha, origen)
    //    Si colisiona con OTRA clave -> sondear PK+1 (resolución de colisión)
    // 3) INSERT si no existe
}
```
- **Nunca** `INSERT OR IGNORE` (sin `UNIQUE` no deduplica).
- `NOT NULL` + `DEFAULT` en todas las columnas no-PK (requisito CRDT).
- Tras el commit el `UnitOfWork`/`NotifyMarkDirty` dispara la sincronización.

## 4. Nueva tabla de producción: **`terceros_asignaturas`** (CRDT)

> Nombre de tabla en `snake_case` (consistente con `salvedades_conflictos`). Modelo C#: `TerceroAsignatura`. Alias funcional solicitado: *"TercerosConAsignatura"*.

### 4.1 DDL **conforme a CR-SQLite**
```sql
CREATE TABLE IF NOT EXISTS terceros_asignaturas (
    id                      INTEGER PRIMARY KEY NOT NULL,   -- PK ÚNICA, NOT NULL, SIN AUTOINCREMENT
    idtercero               INTEGER NOT NULL DEFAULT 0,
    idprograma              INTEGER NOT NULL DEFAULT 0,
    idasignatura            INTEGER NOT NULL DEFAULT 0,
    semestre                TEXT    NOT NULL DEFAULT '',     -- 'I'..'X' | '' = todos
    activo                  INTEGER NOT NULL DEFAULT 1,
    prioridad               INTEGER NOT NULL DEFAULT 0,      -- 0..100 (preferencia declarada)
    veces_asignada          INTEGER NOT NULL DEFAULT 0,      -- frecuencia histórica (F4)
    fecha_ultima_asignacion TEXT    NOT NULL DEFAULT '',
    origen                  TEXT    NOT NULL DEFAULT 'MANUAL', -- MANUAL | HISTORICO | AG_APROBADO
    observaciones           TEXT    NOT NULL DEFAULT '',
    subunidad               TEXT    NOT NULL DEFAULT '',
    created_at              TEXT    NOT NULL DEFAULT '',
    updated_at              TEXT    NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS idx_tas_tercero    ON terceros_asignaturas(idtercero);
CREATE INDEX IF NOT EXISTS idx_tas_asignatura ON terceros_asignaturas(idasignatura);
CREATE INDEX IF NOT EXISTS idx_tas_programa   ON terceros_asignaturas(idprograma, semestre);
```
**Checklist de conformidad CRDT (verificado contra `SyncInitializer`):**
| Requisito | Cumple |
|---|---|
| PK única de una sola columna | ✅ `id` |
| PK `NOT NULL`, **sin** `AUTOINCREMENT` | ✅ `INTEGER PRIMARY KEY NOT NULL` |
| Sin `FOREIGN KEY` | ✅ |
| Sin `UNIQUE` | ✅ (unicidad garantizada por PK determinista) |
| Ningún `NOT NULL` no-PK sin `DEFAULT` | ✅ todos con `DEFAULT` |
| Columna `subunidad` | ✅ |
| Sin vistas dependientes | ✅ |

**PK determinista** (C#): `FNV-1a 32 bits` sobre `"{idtercero}|{idprograma}|{idasignatura}|{semestre}"`, enmascarado a positivo (`& 0x7FFFFFFF`) y con sondeo ante colisión. Ventaja CRDT: **la misma fila lógica creada en dos sedes converge en una única fila** (mismo PK) en lugar de duplicarse.

### 4.2 Registro CRDT
- Añadir `"terceros_asignaturas"` a `Core\Sync\SyncInitializer.CrdtTables[]` (L21–28) → **se sincroniza entre subunidades** (justo lo deseado: el pool es conocimiento compartido).
- **NO** añadirla a `tablesWithViews` (no tiene vistas).
- Filtro de lectura por subunidad con la convención existente: `WHERE (subunidad = @S OR subunidad = '' OR subunidad IS NULL)`.

### 5.1 Resolución del pool por tupla
```csharp
// AgAsignadorTercero.ObtenerCandidatos(idasignatura, semestre, idprograma, subunidad)
// 1) Filas de terceros_asignaturas con activo = 1
//    y (semestre = @Semestre OR semestre = '')
//    y idasignatura = @IdAsignatura y idprograma = @IdPrograma
// 2) JOIN terceros t ON t.id = idtercero WHERE t.activo = 1
// 3) Requisitos: subunidad/departamento (duro por defecto); residencia/tipo/categoría -> blandos (F4)
// 4) Orden de preferencia: prioridad DESC, veces_asignada DESC
```
### 5.2 Efecto en `es_vacante` (verificado en v3, ahora más preciso)
| Motivo | Causa con el nuevo modelo |
|---|---|
| **`SIN_CANDIDATOS`** | **No hay filas** en `terceros_asignaturas` para `(idasignatura, idprograma, semestre)` con `activo=1` → **se resuelve poblando el pool** (M1/M2/M3) |
| **`SIN_DISPONIBILIDAD`** | Hay candidatos pero todos chocan en `(día, bloque)` (**R1**) o `(fecha, hora)` (**R7**) → reparable moviendo franja |
| **`NO_CUMPLE_REQUISITOS`** | Hay candidatos libres pero ninguno pasa el filtro duro (subunidad/departamento) o los requisitos activados |

### 5.3 Fitness
- **F4** ahora usa señal real: `prioridad` + `veces_asignada` (histórico probado) → mejores cruces.
- Beneficio medible: **menos `SIN_CANDIDATOS`** en el panel de vacantes de la Pestaña 2.

## 8. Modelo AG — 3 capas (consolidado, sin `ag_asignatura_tercero`)

```
CAPA 1 — ALGORITMO (memoria + auditoría, NO CRDT)
  AgAula (S) ──1:N──► AgAulaAsignatura (C)
      └──1:N──► AgCorrida (R) ──1:N──► AgIndividuo ══► List<AgGen>
                                              │            └──0:N──► AgViolacion
                                              └──N──► AgBitacora
  Tablas: ag_aula, ag_aula_asignatura, ag_bloque_horario, ag_corrida,
          ag_individuo, ag_gen, ag_violacion, ag_bitacora

CAPA 2 — STAGING EDITABLE (espejo, NO CRDT)
  ag_vinculaciones ──1:N──► ag_sesiones
  Puente: ag_vinculacion_gen   ·   Paridad: ag_salvedades_conflictos
  Vistas: vw_AgVinculacionesDetalle, vw_AgSesionesDetalle

CAPA 3 — PRODUCCIÓN (CRDT, sin cambios en tablas existentes)
  vinculaciones ──1:N──► sesiones        +  ag_promocion
  NUEVA: terceros_asignaturas  ← pool P×C (evidencia histórica) · CRDT
```

### Relación `AgIndividuo` ↔ `List<AgGen>` ↔ `ag_vinculaciones`/`ag_sesiones`
| Relación | Cardinalidad | Significado |
|---|---|---|
| `AgAula` → `AgAulaAsignatura` | 1 : N | C dependientes (`idprograma`+`semestre`) |
| `AgAula` → `AgCorrida` | 1 : N | Varias corridas por aula |
| `AgCorrida` → `AgIndividuo` | 1 : N | Población por generación |
| **`AgIndividuo` → `AgGen` (`List<AgGen>`)** | **1 : N** | **El cromosoma contiene N genes = N tuplas** |
| `AgIndividuo` → `AgViolacion` | 1 : N | Descartes + regla |
| `AgGen` ↔ `AgVinculacion` | N : M (`ag_vinculacion_gen`) | Genes del mismo `(asignatura, docente, aula, ventana)` se **agrupan** en 1 cabeza |
| `AgVinculacion` → `AgSesion` | 1 : N | Expansión α |
| `AgVinculacion` → `Vinculacion` | 1 : 1 | Promoción (copia con remapeo) |

- **`AgGen`** = `(C, P, S, Día β, Hora γ)` + ventana α + `es_vacante` + `motivo_vacante` (granularidad **día/bloque**, como la literatura).
- **`AgIndividuo`** = **solución completa** de un `AgAula`.

### Pipeline de materialización
```
List<AgGen> → agrupar por (idasignatura, idtercero, idaula, ventana)   → cabezas
            → AgPlanificadorTemporal (α, secuencia R6)
            → GeneradorSesionesRecurrentes.Generar(...) por día
            → AcademicDateSyncService.CalculateAdjustment(...)
            → INSERT ag_vinculaciones + ag_sesiones   [estado_ag='BORRADOR_MATERIALIZADO']
            → edición humana (3 Forms en Modo AG)
            → AgSincronizadorCorrecciones (re-sincroniza genes + recalcula fitness)
            → APROBACIÓN (estado_ag='APROBADO')
            → (M2: upsert pool con origen='AG_APROBADO')
            → PROMOCIÓN: copia con remapeo → vinculaciones + sesiones + ag_promocion
```

## 12. Algoritmo (consolidado)

### 12.1 Representación
`AgIndividuo` = `List<AgGen>` ordenado por `posicion`; `AgGen = (C, P, S, β, γ, horas, α, es_vacante, motivo_vacante)`; azar determinista vía `IAgRandomProvider` + `semilla`.

### 12.2 Restricciones
| Regla | Enunciado | Reparación | Peso | Tipo |
|---|---|---|---|---|
| **R1** | Docente no en dos lugares a la misma hora | Elimina tupla conflictiva + reasigna (o Vacante) | 100 | Dura |
| **R2** | Aula no alberga dos cursos simultáneos | Muta franja/día | 80 | Dura |
| **R3** | Mismo curso en días diferentes (si es diario) | Intercambia posiciones | 40 | Dura |
| **R4** | Grupo sin dos C el mismo día, **salvo sábado** (2×4 h o 1×8 h) | Mueve a otro día / admite pareja sábado | 60 | Dura |
| **R5** | Máx. **2 Asignaturas semanales** por grupo (ej. C1: MAR/MIÉ · C2: JUE/VIE) | Reagrupa por semanas | 50 | Dura |
| **R6** | Debe **finalizar** las C de la 1.ª asignación antes de iniciar 1–2 nuevas | Reordena ventanas α por `orden_curricular` | 70 | Dura |
| **R7** | Tercero no en dos grupos a la misma fecha y hora | Reasigna franja | 100 | Dura |
| **BETA/GAMMA** | Día ∉ β / Bloque ∉ γ | Reasignar | 200 | Dura |
| **SOLAPE** | Franjas solapadas en el mismo `aula_ref` (`FranjaHoraria.SeSolapaCon`) | Reasignar franja | 90 | Dura |
| **VACANTE** | Tupla sin docente (`es_vacante=1`) | — (penaliza) | 100 | Blanda-fuerte |
| **COBERTURA** | Asignatura requerida sin tupla | Inserta tupla | 150 | Dura |

### 12.3 Fitness `F = F1 − F2 + 2·F3 + F4 + 2·F5`
| Término | Definición |
|---|---|
| **F1** | Cobertura de C requeridas |
| **F2** | Suma ponderada de violaciones (se resta) |
| **F3** | Escalonado + R5/R6 (**×2**) |
| **F4** | Balance de carga + **afinidad `terceros_asignaturas` (`prioridad`, `veces_asignada`)** + `residencia ↔ sede` |
| **F5** | Preservación de bloques (**×2**) |

### 12.4 Cruce (C#) — OP2/OX/restricciones + reparación en cascada + Vacante
```csharp
internal sealed class AgOperadorCruce
{
    public Result<AgParHijos> Cruzar(AgIndividuo p1, AgIndividuo p2, AgContexto ctx)
    {
        int corte = _random.Siguiente(1, p1.Genes.Count);
        var h1 = Heredar(p1.Genes, 0, corte, p2.Genes, corte, ctx);
        var h2 = Heredar(p2.Genes, 0, corte, p1.Genes, corte, ctx);

        foreach (var hijo in new[] { h1, h2 })
        {
            foreach (var gen in hijo.Genes)
            {
                if (gen.EsVacante) { continue; }
                if (_validador.DocenteDisponible(gen, hijo)) { continue; }

                var alterno = _asignador.BuscarAlterno(gen, ctx, hijo);   // ← lee terceros_asignaturas
                if (alterno.HasValue) { gen.IdTercero = alterno.Value; gen.EstadoGen = AgEstadoGen.Reparado; continue; }

                gen.IdTercero = null; gen.EsVacante = true;
                gen.MotivoVacante = _asignador.DiagnosticarMotivo(gen, ctx);
                gen.EstadoGen = AgEstadoGen.Vacante;
                hijo.Penalizacion += AgPesosFitness.Vacante;              // 100
            }
            var violaciones = _validador.Validar(hijo);                    // R1..R7, BETA, GAMMA, SOLAPE
            hijo.Violaciones.AddRange(violaciones);
            hijo.Estado = violaciones.Exists(v => AgPesosFitness.EsDura(v.Regla))
                        ? AgEstadoIndividuo.Descartado : AgEstadoIndividuo.Apto;
        }
        return Result.Success(new AgParHijos(h1, h2));
    }
}
```
Mutación (4 modos: β/γ, docente, swap, ventana α). Selección: torneo + elitismo. Terminación: generaciones ∪ umbral ∪ estancamiento. I/O: evaluación en memoria; se persiste seleccionado + descartados + `ag_bitacora`.

## 13. Promoción (gate de aprobación + copia con remapeo)
1. Requiere `ag_aula.estado='APROBADO'` **y** `ag_corrida.estado='APROBADA'`; valida `vacantes=0` (o justificación explícita) y `violaciones_duras=0`.
2. **Transacción única:** por cada `ag_vinculaciones` → `INSERT vinculaciones` (remapeo `mapaId`); por cada `ag_sesiones` → `INSERT sesiones (idvinculacion = mapaId[...])`; `INSERT ag_promocion (modo='COPIA_REMAPEO')`; `UPDATE` de estados a `PROMOVIDO`.
3. **En la misma transacción (M2/H2):** `Upsert` en `terceros_asignaturas` con `origen='AG_APROBADO'`.
4. **Fallback `REGENERACION`** si `ag_sesiones` está vacío → `GeneradorSesionesRecurrentes` + `AcademicDateSyncService`.
5. **Re-promoción** idempotente vía `ag_promocion` (`UPDATE` + re-`InsertSesiones`).

## 19. Resumen ejecutivo

- **Nuevo en v4:** la tabla de producción **`terceros_asignaturas`** (CRDT, conforme a `SyncInitializer`, PK determinista) como **fuente única del pool Docente↔Asignatura**, alimentada por **4 mecanismos** (derivación histórica desde `vinculaciones`/`idvinculacion`, hooks automáticos en `FormSesionesAcademicas` y en la promoción, edición manual en `FormTerceros`, y aprendizaje del AG al aprobar).
- **Respuesta a "cómo usar `idvinculacion`":** cada vinculación histórica es **evidencia** `(P, Programa, Asignatura, Semestre)`; `FormVerVinculaciones` *Por Semestre* aporta el agrupamiento/filtros y la derivación se ejecuta contra `vinculaciones` base (la vista no expone `IdAsignatura`).
- **UI:** `FormTerceros` gana la pestaña **"Asignaturas habilitadas"** (grilla + editor + *Importar desde histórico*); `FormVerVinculaciones` gana menú contextual *Habilitar/Sincronizar pool*.
- **AG:** `AgAsignadorTercero` lee el pool CRDT → menos `SIN_CANDIDATOS`, **F4** con señal real (`prioridad`, `veces_asignada`); se elimina `ag_asignatura_tercero`.
- **Compatibilidad total:** `ag_vinculaciones`/`ag_sesiones` son **espejo exacto**; `vw_Ag*` con los mismos alias ⇒ **viáticos, exportables y vistas sin cambios**; los 3 Forms operan en **Modo AG** con la misma UX y **regresión cero** en Modo Determinista.
- **Alcance:** 13 tablas `ag_*` + 2 vistas (V48) + 1 tabla producción CRDT (V49) + 10 archivos existentes tocados de forma **aditiva con defaults**; **`vinculaciones`/`sesiones` intactas**.
