## 1. Análisis de aplicabilidad del AG

### 1.1 ¿Es el problema apto para AG?  Sí, y con una ventaja estructural

### 1.2 La observación clave: el AG **no** debe reimplementar el calendario

Hoy el flujo es:

```
(UI) parámetros → GeneradorSesionesRecurrentes.Generar(...)  → List<Sesion> (fechas)
                                                              ↓
      InsertVinculacion(Vinculacion)  +  InsertSesiones(List<Sesion>)   [1 transacción]
```

Es decir, **`vinculaciones` es la "cabeza" de la tupla** (Periodo, Sede, Programa, Semestre, Grupo, Asignatura, Tercero, Día/Horas) y **`sesiones` es la expansión semanal ya fechada** (cardinalidad 1:N, `sesiones.idvinculacion → vinculaciones.id`).

Por tanto, el AG debe decidir **solo la cabeza + el patrón semanal (Día, Franja)**, y **reutilizar** `GeneradorSesionesRecurrentes` + `AcademicDateSyncService` para materializar las sesiones fechadas. Esto:
- Evita duplicar la lógica de festivos/rangos PRESENCIAL/viáticas (hoy en `btnGenerar_Click`).
- Garantiza que lo promovido sea **idéntico** a lo que el usuario genera hoy (compatibilidad total con viáticos, exportables y vistas).
- Mantiene el nuevo esquema desacoplado y **sin tocar** `vinculaciones`/`sesiones`.

### 1.3 Relación `vinculaciones` ↔ `sesiones` (lo que el AG debe generar)

| Concepto enunciado | Tabla actual | Campo(s) |

| Periodo | `vinculaciones` | `idperiodo` |
| Sede | `vinculaciones` | `idsede` |
| Programa | `vinculaciones` | `idprograma` |
| Semestre (I–X) | `vinculaciones` | `semestre` |
| Grupo (A–Z.. "") | `vinculaciones` | `grupo` |
| Asignatura (C = "Curso" "Materia") | `vinculaciones` | `idasignatura` |

1. Módulo Aula/Salón (S): no se va generar sino que se crea como punto de partida como insumo para el AG, mediante una UI que va desplegando en cadena `idperiodo` + `idsede`+`idprograma`+`semestre` + `grupo` + `modalidadVinculacion` para hacer la selección y generar el encabezado de la vinculación (idvinculacion). De esta forma, el Aula/Salón define mediante `idprograma`+`semestre`= idasignatura dependientes que son los que se van a cruzar con los terceros

2. Módulo Cruzamiento (R): Utiliza un operador de cruce para que a cada asignatura se le asigne un Tercero. Utiliza el AG para generar la tupla S+C+P (Aula/Salón+Asignatura+Tercero) y decidir **solo la cabeza + el patrón semanal (Día, Franja)**, y **reutilizar** `GeneradorSesionesRecurrentes` + `AcademicDateSyncService` teniendo en cuenta las fechas de cuándo inicia y termina cada vinculación, utilizando la fecha de inicio para calcular la fecha final de la sesión de clases (α).

## 3. Tupla y equivalencias

```
Tupla = (Curso C, Docente P, Aula S, Día β, Hora γ)
      = (idasignatura, idtercero, {idperiodo,idsede,idprograma,semestre,grupo,modalidad},
         dia_semana, idbloque_horario)


### Pipeline de materialización

```javascript
List<AgGen> → agrupar por (idasignatura, idtercero, idaula, ventana)   → cabezas
            → AgPlanificadorTemporal (α, secuencia R6)
            → GeneradorSesionesRecurrentes.Generar(...) por día
            → AcademicDateSyncService.CalculateAdjustment(...)
            → INSERT ag_vinculaciones + ag_sesiones   [estado_ag='BORRADOR_MATERIALIZADO']
            → edición humana (3 Forms en Modo AG)
            → AgSincronizadorCorrecciones (re-sincroniza genes + recalcula fitness)
            → APROBACIÓN (estado_ag='APROBADO')
            → (M2: upsert pool con origen='AG_APROBADO')
            → PROMOCIÓN: copia con remapeo → vinculaciones + sesiones + ag_promocion
```


Algoritmo (consolidado)
12.1 Representación
AgIndividuo = List<AgGen> ordenado por posicion; AgGen = (C, P, S, β, γ, horas, α, es_vacante, motivo_vacante); azar determinista vía IAgRandomProvider + semilla.

12.2 Restricciones
Regla	Enunciado	Reparación	Peso	Tipo
R1	Docente no en dos lugares a la misma hora	Elimina tupla conflictiva + reasigna (o Vacante)	100	Dura
R2	Aula no alberga dos cursos simultáneos	Muta franja/día	80	Dura
R3	Mismo curso en días diferentes (si es diario)	Intercambia posiciones	40	Dura
R4	Grupo sin dos C el mismo día, salvo sábado (2×4 h o 1×8 h)	Mueve a otro día / admite pareja sábado	60	Dura
R5	Máx. 2 Asignaturas semanales por grupo (ej. C1: MAR/MIÉ · C2: JUE/VIE)	Reagrupa por semanas	50	Dura
R6	Debe finalizar las C de la 1.ª asignación antes de iniciar 1–2 nuevas	Reordena ventanas α por orden_curricular	70	Dura
R7	Tercero no en dos grupos a la misma fecha y hora	Reasigna franja	100	Dura
BETA/GAMMA	Día ∉ β / Bloque ∉ γ	Reasignar	200	Dura
SOLAPE	Franjas solapadas en el mismo aula_ref (FranjaHoraria.SeSolapaCon)	Reasignar franja	90	Dura
VACANTE	Tupla sin docente (es_vacante=1)	— (penaliza)	100	Blanda-fuerte
COBERTURA	Asignatura requerida sin tupla	Inserta tupla	150	Dura
12.3 Fitness F = F1 − F2 + 2·F3 + F4 + 2·F5
Término	Definición
F1	Cobertura de C requeridas
F2	Suma ponderada de violaciones (se resta)
F3	Escalonado + R5/R6 (×2)
F4	Balance de carga + afinidad terceros_asignaturas (prioridad, veces_asignada) + residencia ↔ sede
F5	Preservación de bloques (×2)

## 2. Arquitectura general (4 capas de datos)

```javascript
┌─ CAPA 0 — PRODUCCIÓN MAESTRA (CRDT, sincronizada) ──────────────────────────────┐
│  terceros_asignaturas   ← POOL Docente↔Asignatura (evidencia histórica + manual)│
│  (se alimenta de `vinculaciones` que son el histórico del negocio)              │
└─────────────────────────────────────────────────────────────────────────────────┘
                                     │  consulta (ITerceroAsignaturaRepository)
                                     ▼
┌─ CAPA 1 — ALGORITMO (memoria + auditoría, NO CRDT) ─────────────────────────────┐
│  AgAula (S) ─1:N─► AgAulaAsignatura (C)                                          │
│      └─1:N─► AgCorrida (R) ─1:N─► AgIndividuo ══► List<AgGen>                    │
│                                        │              └─0:N─► AgViolacion        │
│                                        └─N─► AgBitacora                          │
│  Tablas: ag_aula, ag_aula_asignatura, ag_bloque_horario, ag_corrida,             │
│          ag_individuo, ag_gen, ag_violacion, ag_bitacora                         │
└─────────────────────────────────────────────────────────────────────────────────┘
                                     │  materialización (agrupar + expandir α)
                                     ▼
┌─ CAPA 2 — STAGING EDITABLE (espejo, NO CRDT) ───────────────────────────────────┐
│  ag_vinculaciones ─1:N─► ag_sesiones      ·  puente ag_vinculacion_gen            │
│  paridad: ag_salvedades_conflictos        ·  vistas: vw_AgVinculacionesDetalle,   │
│                                                      vw_AgSesionesDetalle        │
└─────────────────────────────────────────────────────────────────────────────────┘
                                     │  PROMOCIÓN (aprobación + copia con remapeo)
                                     ▼
┌─ CAPA 3 — PRODUCCIÓN (SIN CAMBIOS en tablas existentes) ────────────────────────┐
│  vinculaciones ─1:N─► sesiones      +  ag_promocion (trazabilidad id↔id)         │
│  + (M2) upsert automático del pool en terceros_asignaturas (origen AG_APROBADO)  │
└─────────────────────────────────────────────────────────────────────────────────┘
```

__Flujo funcional completo__

```javascript
Módulo Aula/Salón (S)  → ag_aula + ag_aula_asignatura            [insumo, no genera vinculaciones]
Módulo Cruzamiento (R) → AgCorrida/AgIndividuo/List<AgGen>       [AG: cruza C con P del pool]
                       → materializa ag_vinculaciones/ag_sesiones
Edición humana         → los 3 Forms en Modo AG + Pestaña 2 (tuplas) + AgSincronizadorCorrecciones
Aprobación             → estado_ag = APROBADO (gate duro)
Promoción              → vinculaciones + sesiones + ag_promocion (+ upsert pool)
```
